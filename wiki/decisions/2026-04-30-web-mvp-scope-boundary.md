# Web MVP Scope Boundary Decision

## 결정

1차 웹 MVP는 `서버의 사용자 로컬 폴더 직접 분석`과 `실제 외부 AI 생성`을 제외하고, `브라우저 폴더 선택 + 클라이언트 추출 + 서버 draft 분석 + 승인 가능한 수동 보정 흐름`으로 구현한다.

## 이유

- 현재 배포 구조는 Vercel 서버이며, 사용자의 로컬 파일 시스템 경로를 직접 읽을 수 없다.
- 다만 브라우저 권한 기반 폴더 선택으로 `작업폴더 분석` 요구사항은 유지할 수 있다.
- 구현 문서가 요구하는 핵심 경험은 `폴더와 도메인에서 컨텍스트 초안을 만들고 승인하는 것`이다.
- 초기에 외부 AI 연동까지 묶으면 오류 지점이 늘어나고 검증 범위가 과도하게 커진다.
- MVP의 성공 기준은 `생성 품질 최대화`보다 `흐름 연결과 작업 구조 검증`에 있다.

## 적용 범위

- `workingPath`
  - 프로젝트 생성 시 저장은 한다.
  - 브라우저에서 선택한 폴더 표시용 문자열로 사용한다.
- `source payload`
  - 클라이언트가 선택한 폴더에서 추출한 파일 메타데이터와 텍스트를 서버로 보낸다.
  - 1차 분석의 실제 입력으로 사용한다.
- `domain`
  - 프로젝트 맥락의 보조 입력으로 저장한다.
  - 1차에서는 source payload와 함께 컨텍스트 초안 템플릿에 반영한다.
- `BrandProfile`
  - 초안 생성 후 사용자 보정과 승인 단계를 필수로 둔다.
- `TopicCandidate`
  - 승인된 프로필 기준으로 생성한다.
- `ContentJob`, `ContentAsset`
  - 승인된 프로필과 선택 주제 기준으로만 생성한다.

## 반드시 지킬 규칙

- 컨텍스트 승인 전 콘텐츠 생성 금지
- 브라우저가 폴더 권한을 주기 전 분석 시작 금지
- `workingPath` 문자열만으로 분석 완료 상태처럼 표기 금지
- 검수 없는 즉시 발행 흐름 금지
- 이미지 생성 기능을 암시하더라도 MVP 완료 기능처럼 오인시키지 않기

## 구현 영향

- 프론트는 프로젝트 생성 화면에서 `작업 폴더 선택`과 추출 상태를 함께 다뤄야 한다.
- 백엔드는 컨텍스트 초안을 생성하는 서비스 계층이 `source payload`를 받을 수 있어야 한다.
- 검증팀은 권한 거부, 미지원 브라우저, 빈 추출 결과를 명시적으로 확인한다.

## 재검토 조건

- 업로드 기반 fallback이 추가될 때
- 서버 측 크롤링/파싱 런타임이 도입될 때
- 외부 AI 생성 연동이 안정적으로 붙을 때
