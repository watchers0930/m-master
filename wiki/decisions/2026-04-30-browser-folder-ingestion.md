# Browser Folder Ingestion Decision

## 결정

1차 웹 MVP의 작업폴더 분석은 `브라우저 기반 폴더 선택(File System Access API) -> 클라이언트 측 파일 추출 -> 서버 draft 분석` 구조로 구현한다.

## 이유

- 제품 요구사항상 `작업폴더 분석`은 유지해야 한다.
- Vercel 서버는 사용자의 로컬 경로를 직접 읽을 수 없으므로 서버 직접 스캔 방식은 성립하지 않는다.
- 브라우저 권한 기반 접근은 사용자가 명시적으로 허용한 범위의 파일만 다룰 수 있어 보안 설명이 명확하다.
- 1차 MVP에서 필요한 것은 전체 파일 동기화가 아니라 `컨텍스트 초안에 필요한 텍스트 추출`이다.

## 1차 구현 방식

1. 사용자가 브라우저에서 작업 폴더를 선택한다.
2. 클라이언트가 허용된 확장자만 순회한다.
3. 클라이언트가 파일명, 경로, 확장자, 크기, 추출 텍스트를 만든다.
4. 클라이언트가 프로젝트 생성 또는 컨텍스트 분석 요청과 함께 서버로 payload를 보낸다.
5. 서버는 이 payload와 `domain`을 바탕으로 `BrandProfile` draft를 생성한다.

## 1차 허용 범위

- 브라우저
  - Chromium 계열 기준 `showDirectoryPicker`
- 추출 대상
  - `txt`, `md`, `html`, `json`
  - PDF는 후속 단계 또는 제한적 지원으로 별도 판단
- 서버 입력
  - 추출 본문 전체 또는 길이 제한된 chunk
  - 파일 메타데이터 요약

## 1차 비허용 범위

- 서버의 로컬 절대경로 직접 접근
- 사용자가 선택하지 않은 상위 폴더 재귀 접근
- 이미지/OCR 기반 추출
- 대용량 바이너리 파싱

## 반드시 지킬 규칙

- 폴더 선택은 명시적 사용자 액션으로만 시작
- 브라우저 지원 불가 시 대체 안내 제공
- 금지 확장자와 과대 파일은 추출 전에 제외
- 서버에는 초안 분석에 필요한 텍스트와 메타데이터만 보낸다
- 승인 전에는 추출 결과를 `확정 컨텍스트`로 취급하지 않는다

## 구현 영향

- 프론트는 폴더 선택, 권한 상태, 파일 추출 상태를 별도 상태 모델로 가져야 한다.
- 백엔드는 `POST /api/projects` 또는 `POST /api/projects/:id/context/analyze`가 `source payload`를 받을 수 있어야 한다.
- 검증팀은 브라우저 권한 흐름과 미지원 브라우저 메시지를 필수 시나리오로 본다.

## 재검토 조건

- Safari/Firefox fallback 방식을 정의할 때
- PDF 추출과 chunk 저장 구조를 도입할 때
- source 문서 장기 저장 정책을 설계할 때
