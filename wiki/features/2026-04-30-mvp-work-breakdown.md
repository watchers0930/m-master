# MVP Work Breakdown

## 목적

1차 개발 범위를 역할별로 분해해 병렬 작업이 가능하도록 만든다.

## 1차 개발 범위

- 프로젝트 생성
- 작업 폴더 지정
- 도메인 입력
- 컨텍스트 분석 결과 요약
- 사용자 승인
- 주제 입력 또는 추천
- 블로그 생성
- 인스타그램/페이스북 파생 생성
- 기본 검수
- 결과 확인 화면

## 역할별 작업 분해

### 메인 컨트롤

- MVP 범위 확정
- 우선순위 결정
- 역할 간 의존성 정리
- 최종 승인 기준 정의

산출물:

- 범위 확정 메모
- 역할별 시작 조건
- 최종 완료 기준

### 프로덕트 기획

- 사용자 흐름 문서 작성
- 프로젝트 생성 플로우 정의
- 컨텍스트 승인 플로우 정의
- 콘텐츠 생성 플로우 정의
- 검수 결과 표시 항목 정의
- 예외 케이스 정리

산출물:

- 기능 위키 문서
- 상태 정의표
- 입력/출력 명세

### 디자인

- 프로젝트 생성 화면 구조
- 컨텍스트 분석/승인 화면 구조
- 콘텐츠 스튜디오 구조
- 검수 결과 패널 구조
- 공통 컴포넌트 목록 정의

산출물:

- 화면 와이어 구조
- 컴포넌트 목록
- 상태별 UI 메모

### 프론트엔드

- 라우트 뼈대 구성
- 공통 레이아웃
- 프로젝트 생성 폼 구현
- 컨텍스트 요약 화면 구현
- 콘텐츠 탭 UI 구현
- 검수 패널 구현

산출물:

- 페이지 구조
- 공통 UI 컴포넌트
- 테스트 도메인 확인 가능한 화면

### 백엔드

- Prisma 모델 보강
- 프로젝트 생성 API
- 컨텍스트 분석 작업 모델
- 콘텐츠 생성 작업 모델
- 검수 결과 모델
- 서비스 계층 초안

산출물:

- 스키마 초안
- API/서비스 초안
- 작업 상태 저장 구조

### 검증

- 기능별 검증 체크리스트 작성
- 프로젝트 생성 성공/실패 시나리오
- 컨텍스트 승인 시나리오
- 콘텐츠 생성 시나리오
- 검수 패널 확인 시나리오

산출물:

- 검증 시나리오 문서
- 배포 전 점검 목록

## 의존성

- 기획 완료 전
  - 디자인과 백엔드는 상세 구현을 확정하지 않는다.
- 디자인 기준 수립 후
  - 프론트는 공통 컴포넌트 구조를 확정한다.
- 데이터 모델 초안 후
  - 백엔드는 API와 서비스 구현을 시작한다.
- 프론트와 백엔드 기본 흐름 연결 후
  - 검증이 end-to-end 점검을 시작한다.

## 우선순위

1. 프로젝트 생성
2. 컨텍스트 분석 결과 표시
3. 사용자 승인
4. 콘텐츠 생성
5. 검수 결과 표시

## 완료 기준

- `m-master.vercel.app`에서 프로젝트 생성부터 결과 확인까지 흐름이 이어진다.
- 위키 문서가 구현 기준과 맞게 갱신된다.
- 검증 체크리스트 기준 핵심 흐름이 통과된다.
