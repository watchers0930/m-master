# 검수 패널

## 목적

생성된 3채널 콘텐츠에 대해 브랜드 일치도, 과장 표현, 채널 포맷, CTA 명확성을 빠르게 확인시키고, 사용자가 무엇을 고쳐야 하는지 즉시 판단하게 한다.

## 사용자 흐름

1. 사용자가 스튜디오에서 생성 또는 저장을 마친다.
2. 검수 패널이 각 채널 자산을 기준으로 검수 결과를 로드한다.
3. 사용자는 요약 점수와 문제 목록을 본다.
4. 사용자는 제안된 수정 행동을 선택한다.
5. 필요 시 스튜디오로 돌아가 수정하거나 부분 재생성을 요청한다.
6. 해결 후 재검수를 실행한다.
7. 최종적으로 `내보내기 준비 완료` 상태를 확인한다.

## 입력

- `ContentJob`
- `ContentAsset[]`
- 검수 정책 입력
  - 승인된 `BrandProfile`
  - 채널별 길이/형식 규칙

## 출력

- 검수 요약
  - `brand alignment score`
  - `risk score`
  - `format score`
  - `cta clarity score`
- 문제 목록
  - 채널
  - 문제 유형
  - 짧은 설명
  - 권장 액션
- 채널별 상태
  - `ready`
  - `needs-edit`
  - `blocked`

## 주요 상태

- `review-loading`
  - 검수 결과 로딩
- `review-ready`
  - 결과 표시 가능
- `needs-fix`
  - 수정 필요
- `rechecking`
  - 재검수 중
- `export-ready`
  - 내보내기 가능

## 예외 케이스

- 자산이 아직 없음
  - 검수 실행 차단
- 블로그만 있고 SNS 자산이 없음
  - 누락 채널을 별도 경고
- 점수는 높은데 치명적 금지 표현이 있음
  - 총점보다 개별 치명 항목 우선 표시
- 사용자가 수정 후 재검수 안 함
  - `최종 상태 아님` 경고 필요
- 검수 엔진 실패
  - 마지막 성공 결과와 실패 안내를 분리 표시

## 관련 화면

- `검수 및 내보내기`

## 관련 API/서비스

- `POST /api/assets/:id/review`
- `GET /api/content-jobs/:id`
- 제안 서비스
  - `reviewContentJob(contentJobId)`
  - `buildReviewFindings(contentJobId)`

## 관련 데이터 모델

- 현재 스키마 기준 직접 저장 대상
  - `ContentJob`
  - `ContentAsset`
- 후속 보강 필요
  - `ReviewResult` 또는 동등 구조

## 구현 메모

- 디자인 문서 기준으로 검수는 `점수판`이 아니라 `행동 유도 패널`이어야 한다.
- 따라서 긴 설명보다 `무엇이 문제인지`, `어디를 고쳐야 하는지`, `수정 버튼이 어디 있는지`가 중요하다.
- 경고 항목마다 바로 해당 채널 편집 단계로 돌아가는 액션이 있어야 한다.
- 1차는 발행 기능 없이 `내보내기 준비 상태`까지만 다루는 편이 맞다.
- 검수 항목은 최소 4개로 고정한다.
  - 브랜드 일치도
  - 과장 표현 리스크
  - 채널 포맷 적합성
  - CTA 명확성

## 검증 방법

- 3채널 자산이 있으면 검수 결과가 채널별로 나뉘어 보이는지 확인
- 치명적 금지 표현이 있으면 점수와 무관하게 수정 필요 상태가 되는지 확인
- 수정 후 재검수를 실행하면 상태가 갱신되는지 확인
- 검수 결과에서 스튜디오의 해당 채널/영역으로 복귀 가능한지 확인
- 내보내기 가능 여부가 검수 상태와 연결되는지 확인
