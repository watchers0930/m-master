# 추천 주제

## 목적

승인된 브랜드 컨텍스트를 바탕으로 사용자가 바로 생성할 수 있는 주제를 제안하고, 직접 입력과 추천 선택을 같은 단계에서 처리한다.

## 사용자 흐름

1. 승인된 컨텍스트가 있으면 사용자가 주제 단계에 진입한다.
2. 시스템이 `TopicCandidate` 목록을 로드한다.
3. 사용자는 목적 필터를 선택한다.
4. 추천 카드 중 하나를 선택하거나 직접 주제를 입력한다.
5. 시스템이 최종 선택 주제를 `콘텐츠 스튜디오` 시작값으로 넘긴다.

## 입력

- 승인된 `BrandProfile`
- 사용자 선택 필터
  - `검색 유입`
  - `브랜딩`
  - `전환`
- 직접 입력 주제 문자열

## 출력

- `TopicCandidate[]`
  - `title`
  - `intentType`
  - `score`
  - `rationale`
- 최종 선택 주제

## 주요 상태

- `loading`
  - 추천 주제 조회 중
- `ready`
  - 카드 선택 가능
- `manual-input`
  - 직접 입력 활성
- `selected`
  - 스튜디오 이동 가능
- `empty`
  - 추천 없음

## 예외 케이스

- 추천 주제가 0개
  - 직접 입력을 기본 경로로 전환
- 추천 사유가 빈약함
  - 1차에서는 `브랜드 적합`, `검색 수요`, `전환 적합` 같은 짧은 근거라도 고정 제공
- 직접 입력이 너무 짧음
  - 최소 길이 검증 필요
- 승인되지 않은 프로필로 주제 요청
  - 서버에서 차단

## 관련 화면

- `주제 기획`

## 관련 API/서비스

- `GET /api/projects/:id/topics`
- 제안 서비스
  - `listTopicCandidates(projectId, filters)`
  - `selectTopic(projectId, topicInput)`

## 관련 데이터 모델

- `TopicCandidate`
- 참조 기준
  - `BrandProfile`
  - `Project`

## 구현 메모

- 카드에는 제목 외에 `목적`, `점수`, `짧은 근거`를 함께 보여야 선택이 빨라진다.
- 직접 입력은 추천을 대체하는 기능이지 별도 고급 기능이 아니다. 같은 우선순위로 보여야 한다.
- 추천 주제 선택 후 곧바로 콘텐츠 스튜디오에 진입시키고, 왼쪽 설정 패널에서 주제를 다시 바꿀 수 있게 두는 편이 낫다.

## 검증 방법

- 승인된 프로젝트에서만 추천 목록이 노출되는지 확인
- 필터 변경 시 목록이나 정렬 기준이 변하는지 확인
- 추천 카드 선택 후 스튜디오 시작값으로 전달되는지 확인
- 추천 없음 상태에서 직접 입력만으로 다음 단계 진행 가능한지 확인
- 직접 입력이 `ContentJob.topic`에 정확히 저장되는지 확인
