## 현재 구현 기준 이해

- 웹 MVP의 핵심 선형 흐름은 `프로젝트 생성 -> 컨텍스트 초안 확인/승인 -> 추천 주제 선택 -> 콘텐츠 스튜디오 -> 검수 패널`이다.
- 1차 구현의 목적은 완전 자동 마케팅이 아니라 `작업 폴더와 도메인에서 얻을 수 있는 브랜드 맥락을 승인 가능한 상태로 보여주고, 3채널 초안을 한 화면에서 다루게 하는 것`이다.
- 디자인 문서 기준 주 작업 화면은 `콘텐츠 스튜디오`이며, 검수 패널은 점수 표시보다 `수정 행동 유도`가 중심이다.

## 현재 코드와 맞는 구현 범위

- `Project`
  - 프로젝트 생성과 목록/상세의 기본 루트 모델로 사용 가능하다.
- `BrandProfile`
  - 컨텍스트 초안 저장, 사용자 보정, 승인 상태 저장에 바로 사용 가능하다.
- `TopicCandidate`
  - 추천 주제 카드와 직접 입력 이전 후보 저장에 바로 사용 가능하다.
- `ContentJob`
  - 선택 주제 기준 생성 작업과 상태 추적에 사용 가능하다.
- `ContentAsset`
  - 블로그, 인스타그램, 페이스북 3채널 결과 저장에 사용 가능하다.
- `ImageJob`, `ImageAsset`
  - 1차 구현의 필수 기능은 아니지만, 스튜디오와 검수 패널에서 `추후 연결 예정` 자리표시자 설계는 가능하다.

## 1차 웹 MVP 기능 경계

### 반드시 구현해야 하는 것

- 프로젝트 생성 폼
- 프로젝트 생성 직후 컨텍스트 초안 생성
- 컨텍스트 초안 수정 및 승인
- 추천 주제 리스트와 직접 주제 입력
- 블로그/인스타그램/페이스북 동시 초안 생성
- 채널별 편집 탭
- 검수 결과 요약과 수정 제안 표시

### 1차에서는 단순화해야 하는 것

- 서버 측 로컬 폴더 직접 읽기
  - 현재 Vercel 서버는 사용자 로컬 경로를 직접 읽을 수 없다.
  - 대신 브라우저의 `File System Access API`로 사용자가 폴더를 고르고, 클라이언트가 추출한 텍스트를 서버로 보낸다.
- 실제 도메인 크롤링
  - 1차는 `domain`을 입력받아 컨텍스트 초안에 반영하는 수준으로 제한한다.
- 외부 AI 연동
  - 초안 생성은 deterministic draft 또는 서버 고정 템플릿으로 먼저 연결한다.
- 이미지 생성
  - 엔트리 포인트만 남기고 기능 자체는 후속 단계로 둔다.
- 예약 발행
  - 검수 패널에서 `내보내기/발행 준비 상태`까지만 보여준다.

## 화면별 최소 완료 조건

### 프로젝트 생성

- 프로젝트명, 도메인 입력 가능
- 브라우저 기반 작업 폴더 선택 가능
- 유효성 실패 시 즉시 오류 표시
- 성공 시 프로젝트 상세 흐름으로 이동

### 컨텍스트 초안/승인

- 선택된 폴더에서 추출된 파일 요약 목록 표시
- `summary`, `audience`, `tone`, `cta`, `bannedTerms` 초안 표시
- 사용자 수정 후 승인 가능
- 승인 전에는 다음 단계 진행 제한

### 추천 주제

- 추천 카드 3개 이상 표시
- 선택 주제 또는 직접 입력 주제 중 1개를 확정
- 목적 필터는 `검색 유입`, `브랜딩`, `전환` 3개로 시작

### 콘텐츠 스튜디오

- 좌측 설정 패널, 우측 채널 탭 구조
- 블로그, 인스타그램, 페이스북 자산이 하나의 `ContentJob` 아래 연결
- 저장과 재생성 액션 위치 고정

### 검수 패널

- 점수, 문제 목록, 수정 제안, 채널 상태를 한 화면에서 제공
- 발행보다 `수정 -> 재검수` 흐름을 우선

## 구현팀에 주는 판단

- 프론트는 페이지 중심이 아니라 `프로젝트 생성`, `컨텍스트 승인`, `주제 선택`, `스튜디오`, `검수 패널` 단위 feature로 분리하는 편이 맞다.
- 프론트는 브라우저 권한과 파일 추출을 담당하는 `folder-ingestion` 계층을 별도 feature로 두는 편이 맞다.
- 백엔드는 `프로젝트`, `브랜드 프로필`, `주제`, `콘텐츠 작업`, `검수` 순으로 서비스 계층을 나누고, 컨텍스트 초안 생성 입력으로 `source payload`를 받도록 설계해야 한다.
- 검증팀은 폴더 미선택, 권한 거부, 지원 불가 브라우저, 대용량 폴더 같은 브라우저 측 실패를 명시적으로 체크해야 한다.

## 리스크

- 브라우저가 `File System Access API`를 지원하지 않으면 동일 UX를 보장할 수 없다.
- 대용량 폴더 또는 바이너리 위주 폴더는 추출 시간이 길어질 수 있다.
- 컨텍스트 승인 없이 주제/생성으로 넘어가면 기획 의도와 어긋난다.
- 검수 패널이 채점판처럼만 보이면 수정 행동 유도가 약해진다.

## 후속 기록 필요 항목

- 추출 파일 메타데이터와 본문 텍스트를 저장하는 `SourceDocument` 계층 도입 여부
- `File System Access API` 미지원 브라우저 fallback 방식
- ReviewResult 모델 추가 또는 대체 구조 결정
- 이미지 스튜디오 연결 시 콘텐츠 스튜디오와 상태 공유 방식 정의
